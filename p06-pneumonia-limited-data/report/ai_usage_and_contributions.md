# AI usage and contributions

This statement records how AI assistance was used in this project. It should be reviewed and, where necessary, personalized by the author before submission.

## Tools used

- **opencode** command-line coding assistant, powered by the model identified in the session as `opencode/deepseek-v4.1-flash-free`.
- Standard Python scientific stack: PyTorch, torchvision, scikit-learn, pandas, NumPy, matplotlib, seaborn, MedIMeta.
- Shell commands executed on the author's Windows machine for environment setup, dataset inspection, training, evaluation, and analysis.

## What the AI assistant did

The AI assistant was used for:

1. **Project scaffolding.** Creating the directory structure, configuration files, data wrapper, model definitions, training/evaluation entry points, subset-generation script, analysis utilities, and reproducibility runner.
2. **Implementation and debugging.** Writing the MedIMeta wrapper, fixing the `transform=None` behavior, fixing smoke-mode epoch overrides, fixing the evaluation confusion-matrix format bug, preventing unnecessary pretrained-weight loading during evaluation, and adding memory-safe options.
3. **Experiment orchestration.** Running baseline and proposed training for seeds 42–44, running one-time validation/test evaluation, and generating aggregate tables, figures, bootstrap statistics, and Grad-CAM visualizations.
4. **Documentation.** Drafting the README, decision log, notebooks, and this report from the actual saved results.

## What the author did

The author:

- selected the project topic, dataset, and the limited-data framing;
- provided the local environment and placed the MedIMeta data in the project;
- set the requirement to use a fixed 25% subset and a scratch-CNN baseline;
- directed the workflow, including the decision to stop further training and ablations when the host ran out of memory;
- reviewed the outputs and is responsible for the final submission.

## Verification of reported numbers

All reported metrics were computed from saved files in `results/` by the project's own scripts:

- `results/*/seed*/metrics_val.json` and `metrics_test.json`
- `results/*/seed*/predictions_*.csv`
- `results/summary_table.csv` and `results/summary_table.md`
- `results/bootstrap_comparison.json`
- `results/bacterial_viral_confusion.json`

No result was typed by hand from memory or copied from an unfinished run. Incomplete ablation runs were removed so that partial results cannot be mistaken for completed experiments. The test split was evaluated only for the six final main models (3 baseline + 3 proposed), with one-time markers under each `seed` directory.

## Limitations of AI assistance

- The AI assistant cannot independently verify clinical validity, patient-level leakage, or dataset licensing. Those checks remain the author's responsibility.
- AI-generated code and text can contain errors. The author should review the code, the report, and the references before submission.
- The model occasionally produced environment-specific workarounds (reduced batch size, single-threaded/multi-threaded settings, `num_workers=0`). These are documented in `logs/DECISIONS.md` and are visible in the saved run configs.
- The AI assistant did not invent experimental results. Where experiments were not completed (ablations, data-efficiency models), the report says so explicitly.
